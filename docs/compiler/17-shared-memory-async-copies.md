# Shared-memory staging with native asynchronous copies

The compiler now translates Emmy's CpAsyncCopy, CpAsyncCommit, CpAsyncWait and staged LdmatrixLoad nodes directly to native PTX. The shared path works with our m16n8k16 tensor-core implementation and with a generated scalar f32 matmul. The supplied public m01_matmul_512 now passes on the hosted runner as well.

The input remains the unchanged Kernel IR generated by pinned Emmy 0.3.11. This adds emission support and an independent test model; it does not introduce a lowering pass, rewrite schedules or translate reference CUDA.

## Follow the code

The statement dispatch and shared-allocation logic are in [compile.py](../../compile.py). Copy emission, shared slab addressing and staged matrix loads are in [ptx_tensor.py](../../ptx_tensor.py).

| Emmy statement | Native PTX |
| --- | --- |
| CpAsyncCopy, 16 bytes | cp.async.cg.shared.global |
| CpAsyncCopy, 4/8 bytes | cp.async.ca.shared.global |
| CpAsyncCommit | cp.async.commit_group |
| CpAsyncWait | cp.async.wait_group with the IR's group value |
| Staged A fragment load | ldmatrix.sync.aligned.m8n8.x4.shared.b16 |
| Staged ordinary B fragment load | ldmatrix.sync.aligned.m8n8.x2.trans.shared.b16 |
| Staged transposed B fragment load | ldmatrix.sync.aligned.m8n8.x2.shared.b16 |

The generated suite currently exercises 16-byte copies. Recognizing 4/8-byte forms in the emitter is not a claim that those widths have fresh end-to-end coverage. The instruction and completion semantics are documented in NVIDIA's [PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/).

`cp_async_copy()` computes a global source address and shared destination address from Emmy's original indices. An optional lane_index is added to the slab's base coordinates before flattening. The copy moves bytes directly into shared memory; it does not allocate a tensor-data staging register for each copied element. We check copy size, address spaces, matching source/destination element types and base alignment. The supplied scheduler determines chunk offsets/alignment; the NumPy model checks those offsets on the generated examples.

Our shared-symbol bases already hold shared-state addresses. The emitter narrows them to u32 for cp.async/ldmatrix operands; it does not apply an additional generic-to-shared conversion to an already shared address. Global pointers remain u64.

## Swizzled shared addresses

Both the copy producer and matrix-load consumer must use the same layout. We flatten the complete element coordinate e first, then implement the layout carried by Emmy:

```text
physical_element = e XOR (((e >> shift) AND mask) << 3)
B32:  shift=6, mask=1
B64:  shift=6, mask=3
B128: shift=6, mask=7
```

The copy remains contiguous inside its 16-byte chunk. The XOR changes the chunk's shared-memory placement. `shared_slab_address()` emits ordinary integer shifts, masks and XOR; it does not change the IR indices or change a swizzle to NONE.

The emitter also recognizes an explicit @shift override, with constraints that preserve the contiguous chunk. The current generated coverage establishes the three base modes, not every possible override. Shared slabs are currently two-dimensional; higher-rank transport and other layout families fail explicitly.

For staged matrix loads, each warp lane supplies a shared row address. The A path uses x4. B uses x2.trans for an ordinary K-major slab or plain x2 when Emmy marks B as transposed. We retain Emmy's register-fragment layout and issue the existing native MMA afterward.

## Completion and buffering

A commit closes a thread's current copy group. A wait with group=0 completes all committed groups; wait_group 2 leaves at most two groups in flight. The emitter preserves each operation and the subsequent block barriers in their original order. A normal block barrier is not substituted for a copy wait.

The generated tests cover single, double and triple buffering. Triple-buffered kernels prefetch future slabs, commit groups, wait for the older slab, synchronize, load fragments and compute. The producer and consumer use the same ring-slot expressions. This required adding integer division and remainder to the index-expression emitter. Their signed truncation semantics are distinct from floating tensor division and from Python floor division.

The TILE knob's /k field counts MMA atoms, not individual K elements: /k2 means 32 K elements for a k16 atom, and /k4 means 64. Initial probes using /k32 and /k64 requested much larger slabs than intended and were rejected upstream. The saved initial probe report explains those attempts; corrected source-level schedule settings generate the supported cases. No Kernel IR was patched to correct them.

## Dynamic shared-memory allocation

Small shared arrays still use static declarations when meta.json requests zero dynamic bytes. If metadata supplies a positive dynamic budget, `Smem` allocations are laid out with their declared alignment in one module-level `.extern .shared` arena. Allocation beyond that supplied budget is rejected. The launch's smem_bytes is not changed.

This matters for the public 512×512 matmul. Its two slabs total 73,728 bytes, and its supplied metadata requests precisely that dynamic allocation. Declaring both slabs statically exceeded the local sm_89 static shared-memory limit. The arena now uses the requested dynamic storage, without also allocating duplicate static slabs.

## Why the IR reference files changed

[tools/ir_reference.py](../../tools/ir_reference.py) and [tools/tensor_reference.py](../../tools/tensor_reference.py) are our NumPy test interpreter. They are not Emmy's IR files.

The tensor checker now queues each lane's copies, closes groups at actual commit nodes, and materializes completed groups at wait nodes. It applies the shared layout to logical element reads, models the resulting numerical fragments and checks uninitialized/out-of-bounds accesses. A unit test executes actual generated copy/commit/wait statements and verifies that a matrix read fails before the wait and succeeds afterward. This models ordering for our generated schedules; it is not a general GPU memory-race or cycle-accurate simulator.

The new scalar matmul also exposed a checker bug: an outer staging-loop scope discarded updates made by an inner seed=False loop to state initialized by Init. The GPU already matched the original independent NumPy expression. The checker now retains those mutable-state updates while keeping ordinary locals scoped. No generated IR or original expected array was changed to fix this.

The harness reports a GPU-versus-IR mismatch as a failure even when the original-expression comparison passes, so a checker discrepancy remains visible.

## Validation and reproduction

[The generated shared-suite report](../../review/matmul/shared-validation.json) contains nine passing cases against both original expression and typed-IR references: eight tensor-core schedules and one scalar f32 matmul. Coverage includes B32/B64/B128 layouts, multiple K iterations, buffered groups, multiple warps, transposed B and both operand staging paths. One additional attempted irregular M/N staging schedule is rejected by Emmy and remains out of scope for that configuration. It is not included in the nine passes.

[The public report](../../review/shared-matmul/public-validation.json) records m01_matmul_512 passing against its original expected array on the hosted GPU. The full large scalar schedule was not interpreted by default; it is not reported as a second independent IR-reference pass. The optional --ir-reference flag enables that slower check.

The nine previous global-transport cases and eleven public pointwise/reduction/normalization cases were also rerun. Reports are [global transport](../../review/matmul/global-validation.json) and [public regression](../../review/native-math/async-regression.json). Those checks retain both numerical references.

All 47 local test methods pass. Across this increment's hosted checks, 30 cases pass the original-expression expectation; 29 also have a passing typed-IR comparison, and the large public m01 uses its original expectation only. The historical full regression matrix was not rerun.

Local sm_89 disassembly confirms LDGSTS, LDSM and HMMA instructions, plus the copy dependency barriers. The single-warp staged example used 16 physical registers, 768 bytes of static shared memory and no spills: [assembly statistics](../../review/shared-matmul/single-warp-assembly.txt), [SASS](../../review/shared-matmul/single-warp.sass). These are local observations, not a tuned-performance claim or the hosted sm_120 JIT's final instruction stream.

Run in Ubuntu from the repo root:

```bash
python tools/test_matmul.py --suite shared --runner
python tools/test_matmul.py --reuse --runner
python tools/test_public_matmul.py --runner
python -m unittest discover -s tests -p 'test_*.py'
```

The shared generator retries the upstream-rejected shape/schedule and records that failure separately. Strict --reuse requires a valid proof and therefore cannot reuse the rejected fixture. All new successful fixtures retain dump-checked Emmy provenance.

Original competition files are unchanged. Only our compiler's PTX is uploaded; tests never upload reference CUDA/PTX or make a final competition submission. Include all three compiler files at the repository root: compile.py, ptx_math.py and ptx_tensor.py.

The next public matmul gap is m02's atomic accumulation. Arrayed fragment families, fused fragment epilogues, TMA and WGMMA remain unsupported. The new copy transport does not establish coverage for every layout, dtype or schedule.
