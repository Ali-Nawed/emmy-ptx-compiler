# p00: Kernel IR -> Emmy CUDA -> nvcc PTX

These files are educational references, separate from our submission compiler.

- `p00.ir.txt`: supplied readable Kernel IR.
- `p00.emmy.cu`: exact copy of the competition's supplied `k_add_pointwise.ref.cu`, generated by Emmy. Emmy was not rerun to regenerate it.
- `p00.nvcc.ptx`: compiled from that CUDA using Ubuntu's CUDA 12.0 nvcc.

Command from this directory:

```bash
nvcc -ptx -arch=sm_89 -lineinfo p00.emmy.cu -o p00.nvcc.ptx
```

`-lineinfo` adds `.loc` directives mapping instructions to CUDA source lines. The checked-in PTX contains the absolute source location from this run.

## What to compare

| CUDA | Generated PTX |
|---|---|
| Pointer parameters | `.param .u64`, then `ld.param.u64` |
| Global thread index | `%ctaid.x`, `%ntid.x`, `%tid.x`, then `mad.lo.s32` |
| `if (_gid < 64)` | `setp.gt.s32 ..., 63` and a predicated branch to exit |
| `a0 * 2` | `shl.b32 ..., 1` |
| Float element offset -> byte offset | `mul.wide.s32 ..., 4` |
| Pointer conversion | `cvta.to.global.u64` |
| Input reads | Four `ld.global.f32` instructions |
| Two additions | Two `add.f32` instructions |
| `float2` output store | `st.global.v2.f32` |
| End of kernel | `ret` |

The compiler reorders some loads and additions while preserving their dependencies. We do not need identical PTX text; our independently written emitter must preserve behavior and the launch contract.

The generated PTX assembles locally with `ptxas -arch=sm_89`. A hosted execution check was not completed because automatic approval review rejected the upload. This reference pipeline must not be called by the competition submission compiler.
