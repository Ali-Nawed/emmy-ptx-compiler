# Direct reduction lowering

These snapshots were generated by our own compile.py directly from the supplied Kernel IR. There is no intermediate reduction IR and no CUDA/nvcc code-generation step.

All eight public MVP problems passed the hosted runner after this change. The reduction maximum absolute errors were:

| Problem | Maximum absolute error |
|---|---:|
| r01_array_sum | 3.815e-06 |
| r02_big_sum | 1.526e-05 |
| r03_mean | 9.313e-10 |
| r04_row_sum | 5.722e-06 |

All four reduction snapshots also assemble locally for sm_89. These checks do not establish hidden-set correctness.

## Read the code in this order

1. compile(): decode tile axes; bind lane and warp; require complete cooperative blocks so all threads reach block barriers.
2. strided_loop(): initialize the sum before the loop; emit a loop condition, body and increment.
3. statement(Accum): update the same carried register each iteration.
4. statement(WarpShuffle): exchange partner states with XOR shuffles; execute the IR's combine_states assignments.
5. statement(Smem/Cond/Write/Sync): each warp leader writes a partial result and all threads synchronize.
6. tree_halve(): one lane per participating warp combines pairs of shared slots; every block thread reaches each barrier; finally load slot zero into every thread's state.
7. Final Cond/Write: the designated thread writes the result. r03 adds division by the count; r04 flattens row/column indices.

Current scope: f32 sum accumulators, flat power-of-two per-warp shared trees, static tile axes, complete cooperative blocks, and simple integer predicates. Other reductions and advanced schedules fail explicitly. Grouped memory operations are currently scalarized. Future work includes wider node/operator coverage and additional generated shape tests.

To regenerate from the repository root:

```bash
.venv/bin/python compile.py problems/r01_array_sum/k_sum_1_reduce.ir.json > review/reduction-ptx/r01_array_sum.ptx
```
