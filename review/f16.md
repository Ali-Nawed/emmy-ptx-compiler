# Half-precision data support

compile.py still translates Emmy Kernel IR directly into PTX. This change adds
floating-point type bookkeeping, not an intermediate IR.

## Memory and registers

- element_bytes(dtype) supplies 2 for f16 and 4 for f32. Both flattened element
  indices and grouped memory offsets use the actual buffer element size.
- f16 loads read b16 bits into an h register, then use cvt.f32.f16 to produce an
  exactly representable f32 working value.
- f16 stores narrow using cvt.rn.f16.f32 and write b16 bits. Parameter pointers
  stay u64 regardless of buffer element type.
- value_dtypes records the semantic dtype of each floating SSA name. values
  continues to record the working register that holds it.

## Arithmetic and rounding

The initial implementation uses f32 working arithmetic. Before an f16 operation,
operands with a wider semantic dtype are narrowed. After an f16 assignment the
result is immediately rounded to half and widened back to an f32 working
register. This preserves an intermediate half result between multiply and add;
waiting until the final store would change some answers.

round_half emits:

```ptx
cvt.rn.f16.f32 %half_bits, %working_value;
cvt.f32.f16 %rounded_working_value, %half_bits;
```

The copy operation handles explicit conversion assignments present in sum
epilogues. A store also converts according to the destination buffer's dtype,
including a f32 mean calculation written into a half output.

PTX conversion reference: https://docs.nvidia.com/cuda/archive/12.1.1/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cvt

## Reduction state

Emmy's generated f16 tests specify f32 accumulator state, shuffles and shared
scratch. These remain f32. Half input values are promoted on load; only a typed
half assignment or half output store narrows the result. Other accumulator
dtypes and half shared-memory arrays remain unsupported explicitly.

## Validation

- All 32 default f16/f32 fixtures compile and assemble locally.
- All 16 default f16 cases and all 16 f32 cases pass on the competition RTX 5090.
- Eight f16 input-pattern variants pass exact numeric comparisons (rtol=atol=0).
  They cover subnormals, finite large values, half-intermediate rounding and
  cancellation that exposes incorrectly narrowed accumulators.
- Four fresh Emmy-generated f16 cases pass: add, scale/shift and sum at length
  1024, plus row sum at shape 3x1024.
- All eight official MVP cases still pass on the hosted runner.
- Reference-oracle and high-precision result-checker unit tests pass.

Reports: tests/extended/results.json, review/f16-edge-results.json,
tests/extended-f16-large/results.json and review/mvp-f16-results.json.
Only our compiler's PTX was uploaded. This is tested coverage, not a claim that
every possible half-precision Kernel IR or hidden test is supported.
